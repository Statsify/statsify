# site

statsify.net: a [TanStack Start](https://tanstack.com/start) app served by Nitro's Node preset behind nginx and Cloudflare.

```sh
pnpm site dev        # http://localhost:7828
pnpm site build      # .output/ (with .br and .gz copies of its text files), then scripts/check-public-output.ts
pnpm site start      # node .output/server/index.mjs on PORT (7828) and HOST (127.0.0.1)
```

7828 spells STAT on a phone keypad. To serve the site through a proxy or tunnel, point it at `pnpm site start` and set `site.publicUrl` to the public origin. The dev server answers only `localhost`; keep it that way, since it serves files from the whole repo.

Translations live in `locales/<locale>/site.json`; English is served unprefixed and other locales under `/{locale}/`.

Design tokens come from `@statsify/tokens`; fonts in `public/fonts/` are Minecraft, Mona Sans (OFL; instanced and subset as Statsify Sans, see `src/styles/fonts.css`) and Noto Sans subsets (OFL).

## Running it locally

The site reads everything through the API's `/rpc` procedures and never calls Hypixel itself, so it needs the API running.

1. Start MongoDB and Redis (`compose.dev.yml`).
2. Copy `config.schema.js` to `config.js` at the repo root and fill in the keys below. With `api.ignoreAuth: true` the API accepts any request, so `site.apiKey` can stay empty on your machine.
3. From the root: `pnpm build`, then `pnpm api start` and `pnpm site dev`.

A fresh database has no players. Open `/player/<name>` and use "Look up on Hypixel": with `environment: "dev"` there's no Turnstile widget, and the API needs `hypixelApi.key` for the lookup.

The component gallery is at `/dev/gallery` on the dev server: every shared component in every state, including each error and empty state, on fixture data. It never ships (`scripts/check-public-output.ts` fails the build if it does).

## Config keys

| Key | Read by | What it does |
|---|---|---|
| `apiClient.route` | site | The API's origin, e.g. `http://localhost:3000`. |
| `site.apiKey` | site | The site's own API key, with the `SITE` role. Never the bot's. |
| `database.redisUrl` | site | The API's Redis, which also holds rendered unfurl images and their render locks. |
| `site.publicUrl` | site | The origin the site is served from, for absolute URLs in Open Graph tags, oEmbed and sitemaps. |
| `site.indexable` | site | Default true. False for a staging deploy: every response says `X-Robots-Tag: noindex`, the sitemaps 404 and robots.txt lists no sitemap. |
| `site.turnstile.siteKey`, `site.turnstile.secretKey` | site | Cloudflare Turnstile for the lookup button. Without a secret, lookups are refused outside `environment: "dev"`. |
| `site.renderWorkers` | site | Threads in the unfurl image render pool, 1 to 3. Default 2. |
| `site.hypixelBudget` | API | Hypixel calls the site's refresh and lookup may make per 5 minutes, across all visitors. 0 switches them off. A stale profile's update once it opens uses at most two-thirds of it. |
| `sentry.siteDsn`, `sentry.tracesSampleRate` | site | Optional error reporting. |
| `environment` | site | Only `"dev"` relaxes anything (Turnstile, above). A missing value counts as production. |

## Where things are

- `src/routes`: one file per route. Page routes set their edge cache in `headers` with `cacheHeaders()` (`src/lib/cache.ts`). `src/routeTree.gen.ts` is generated by the build.
- `src/features/<page>`: each page's components and loaders.
- `src/components`: shared pieces, with the Minecraft-styled primitives in `src/components/ui`.
- `src/server`: server-only code (`*.server.ts`): config, the API client, the `/api/rpc` proxy, images, sitemaps and Turnstile.
- `src/start.ts`: the security and cache headers on every response. Errors are never cached at the edge.
- `packages/contract`: the oRPC contract the site and the API share. `apps/api/src/site` is the API side.
- `packages/catalog`: stat labels, colors and layouts, shared with the bot's cards. `packages/profiles` holds the bot's cards, which the site renders for unfurl images.

The docs are this README and the comments beside the code: each route file says what it serves and how long it's cached.

## Before a pull request

- Run the repo's checks from the root: `pnpm build --concurrency=3 && pnpm typecheck --affected --concurrency=3 && pnpm lint --affected --concurrency=3 && pnpm test --run --maxWorkers=2`.
- Look at every page you change at 375 and 1440 px wide, and at the gallery for a shared component.
- A procedure the browser calls through `/api/rpc` (a client-side navigation runs the route's loader in the browser) has to be on the allow-list in `src/server/rpc-proxy.server.ts`, or the page 404s on a client-side visit.
- New strings go in `locales/en-US/site.json`.
