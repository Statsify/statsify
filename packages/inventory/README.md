# @statsify/inventory

Draws Minecraft items, text, tooltips and inventories from a resource pack, in the browser or in
Node. Nothing is pre-rendered and no Mojang assets ship with it: drop in a 26.3 pack
(or the 26.3 client jar) and every icon is drawn from it, then cached.

## Packs

`loadPack` takes a zip or jar as a `Blob`, bytes or a URL. A `PackStack` layers packs the way the
game does, lowest priority first, so a texture-only pack can sit on top of a vanilla one.
Swapping a stack swaps every icon, since cache keys start with the stack's hash.

```ts
import { ItemRenderer, IconCache, PackStack, loadPack } from "@statsify/inventory";

const stack = new PackStack([await loadPack(vanillaZip), await loadPack(userPack)]);
const renderer = new ItemRenderer(stack, { cache: new IconCache() });

const icon = await renderer.render({ id: "minecraft:red_wool" }, 4); // a 64 × 64 canvas
```

Older packs load as 26.3's layout, so they stack over a 26.3 pack the same way. A 1.8.9 pack (or
the 1.8.9 client jar) gives its textures and models under their 26.3 names. Its 3D models get the
turn 1.8.9 gave every 3D item in code, its compass and clock strips show the frame a slot shows,
and its glint is tinted and moved the way 1.8 did it. Chests, heads and banners stay 26.3's, which
draws them in code. A stack needs at least one 26.3 pack, which has the item model definitions.
Another version needs only its tables in `UPGRADES` (`src/core/pack.ts`).

## Items

- Flat items with tints: leather dye, potion colours, spawn eggs.
- Block items in 3D, through the model's gui transform with the GUI's lighting. A small software
  rasterizer draws them, so they match the game pixel for pixel and need no WebGL.
- Player heads (the default skin, or `item.skin`, a textures.minecraft.net URL, which the page
  can fetch over https), mob heads, chests.
- The enchantment glint, and animated textures by game tick: `render(item, scale, tick)`.

`legacyItem(id, damage)` turns a 1.8 id and Damage value into a 26.3 item. Its table is
generated by `pnpm generate <26.3 jar or pack zip> <1.8.9 jar>` from minecraft-data and checked
against that pack, along with the 1.8.9 texture names, paired up through the two versions' models.

Icons are cached in IndexedDB. Bump `VERSION` in `src/core/icon-cache.ts` whenever a change draws
icons differently, so browsers drop the old ones.

## Text and tooltips

`TextRenderer.load(stack)` reads the pack's default font: ascii.png plus 26.3's accented and
non-Latin sheets, and unifont for everything else. It draws § codes and JSON text components.
26.3 ships unifont (GNU Unifont) with the launcher's assets, not the jar, so a pack only has it
when it carries `font/include/unifont.json` and `font/unifont.zip`. Without them, a CSS font is the
fallback for those characters. `drawTooltip` draws 1.8's tooltip box, and
`tooltipLines` gives an item's name, lore and Unbreakable line, minding HideFlags.

## Inventories

`InventoryRenderer` draws a whole container: the pack's chest screen (or a plain panel for other
sizes), the title, and each slot's icon, count and 1.8.9 durability bar. An item the pack can't
draw leaves its slot empty and logs the error once.

```ts
const renderer = await InventoryRenderer.load(stack);
const canvas = await renderer.draw(slots, { rows: 6, cols: 9, scale: 3, title: "Quick Buy" });
const tooltip = renderer.tooltip(slots[0], 3, 0);
```

It draws on `OffscreenCanvas` in the browser. In Node, like the Discord bot, set the skia-canvas
backend first, and `draw` returns a skia-canvas `Canvas` (typed as `OffscreenCanvas`).
skia-canvas is an optional peer dependency.

```ts
import { setCanvasBackend } from "@statsify/inventory";
import { skiaCanvas } from "@statsify/inventory/node";

setCanvasBackend(skiaCanvas);
```

## Adapters

- `fromHypixelNBT(data)`: Hypixel's gzipped NBT, like the Pit's `inv_contents`, as items.
  `playerInventoryOrder` puts a player inventory's hotbar last, as the game shows it.
- `fromBedwarsQuickBuy(favourites)`: the 9 × 6 BedWars shop open on Quick Buy, with each
  item's count, cost and description. `src/adapters/bedwars-shop.ts` holds the shop as
  Hypixel's own NBT has it.
- `fromBedwarsHotbar(favoriteSlots)`: a BedWars hotbar from `favorite_slots`, as the Hotbar
  Manager shows it. Without one, the default hotbar.
- `fromDuelsKit(layout, key)`: a Duels `layout_*` kit. The key (`layout_uhc_duel_layout`,
  `layout_mw_duel_herobrine`, `layout_sw_duel_kit_mini_solo_scout`) picks the mode's kit in
  `data/duels-modes.json`, so items get the count, name and tooltip the game gives them, and
  Blitz and SkyWars kits get the armour their picker lists. Armour tokens in older layouts go
  to the armour slots, since the game equips armour. A token no dumped kit has is drawn from the
  Bukkit material it ends in (`hype_train_minecart_7`). Without a layout, it's the game's default
  layout: the single-kit modes in `DUELS_DEFAULT_KEYS` and every kit in `DUELS_KITS`.
- `fromTntGamesLayout(layout, key)`: a TNT Games layout by its `TNTGames` key (`tntrun`,
  `pvprun`, `spleef`, `wizards`, `tnttag`, all in `TNT_GAMES_LAYOUTS`), with the editors' items
  from `data/tnt-games.json`. Without a layout, the game's default one.
- `fromLegacyKit(layout)`: a kit of 1.8 `"id,damage"` values by slot, as Mega Walls'
  `<class>Inventory`, Blitz's `<Kit>Inventory` and classic Walls' `InventoryLayout` send it.
- `fromSkyWarsKit(layout)`: a SkyWars `kit_…_inventory`, which names items by their Bukkit
  material (`legacyMaterial(name, damage)`) and lists enchantment ids on enchanted ones.

`data/duels-modes.json` and `data/tnt-games.json` come from the game: open the layout editors
with the StatsifyDump ChatTriggers module running, then `pnpm build` and
`node scripts/import-dump.ts <dump.json> …`
with the last export of each dump session. Open each kit's editor from its picker before moving
anything: the picker shown next names the kit, and only an unsaved kit shows the default.
An item's `tooltip` holds the lines under its name as the game drew them, enchantments and
attributes included.

Kits come back as 40 slots: the hotbar, the three main rows, then boots to helmet in 36 to 39.
`ARMOR_SLOTS` lists the armour slots helmet first, as the inventory screen shows them.

## `<mc-inventory>`

```ts
import "@statsify/inventory/mc-inventory";

const inventory = document.querySelector("mc-inventory");
inventory.pack = stack;
inventory.slots = fromBedwarsQuickBuy(favourites);
```

```html
<mc-inventory layout="shop" label="Quick Buy" scale="3"></mc-inventory>
```

Attributes: `rows`, `cols`, `scale`, `label` (the title; `title` would also open the browser's
own tooltip), `layout` (`chest`, `large-chest`, `shop`, `hotbar`) and `freeze`, which stops
animations. Tooltips follow the cursor, flip at the window's edges and open on tap.

Every inventory on a page animates on one clock, redrawing only its moving slots, and stops
while it's off screen or the tab is in the background.

## React

```tsx
import { Inventory } from "@statsify/inventory/react";

<Inventory pack={stack} slots={slots} layout="shop" label="Quick Buy" scale={3} />;
```

`Inventory` takes the element's properties and attributes as props. It's a client component that
loads `<mc-inventory>` in the browser, so it's safe to server render. React is an optional peer
dependency.
