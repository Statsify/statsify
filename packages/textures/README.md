# @statsify/textures

Draws Minecraft items, text, tooltips and inventories from a resource pack, in the browser or in
Node. Drop in a 26.3 pack (or the 26.3 client jar) and every icon is drawn from it, then cached, or
draw from an [atlas](#atlas) of icons drawn ahead of time.

## Packs

`loadPack` takes a zip or jar as a `Blob`, bytes or a URL. A `PackStack` layers packs the way the
game does, lowest priority first, so a texture-only pack can sit on top of a vanilla one.
Swapping a stack swaps every icon, since cache keys start with the stack's hash.

```ts
import { ItemRenderer, IconCache, PackStack, loadPack } from "@statsify/textures";

const stack = new PackStack([await loadPack(vanillaZip), await loadPack(userPack)]);
const renderer = new ItemRenderer(stack, new IconCache());

const icon = await renderer.render({ id: "minecraft:red_wool" }, 4); // a 64 × 64 canvas
```

Older packs load as 26.3's layout, so they stack over a 26.3 pack the same way. A 1.8.9 pack (or
the 1.8.9 client jar) gives its textures and models under their 26.3 names, and block items draw
from its item models, as 1.8.9 drew them. Its 3D models get the
turn 1.8.9 gave every 3D item in code, its compass and clock strips show the frame a slot shows,
and its glint is tinted and moved the way 1.8 did it. Chests, heads and banners use 26.3's models,
which are drawn in code, and banners keep 26.3's pattern textures, since 1.8's are masks. A stack
needs at least one 26.3 pack, which has the item model definitions.

## Items

- Flat items with tints: leather dye, potion colors, spawn eggs.
- Block items in 3D, through the model's gui transform with the GUI's lighting. A small software
  rasterizer draws them, so they match the game pixel for pixel and need no WebGL.
- Player heads (the default skin, or `item.skin`, a textures.minecraft.net URL, which the page
  can fetch over https), mob heads, chests, shulker boxes.
- Banners and shields with their patterns: `item.patterns`, as 26.3's `banner_patterns` component
  has them (`{ pattern: "minecraft:border", color: "red" }`), and a shield's `item.baseColor`.
  A banner's base color is in its id.
- The enchantment glint, and animated textures by game tick: `render(item, scale, tick)`.

`legacyItem(id, damage)` turns a 1.8 id and Damage value into a 26.3 item. Its table is
generated by `pnpm generate <26.3 jar or pack zip> <1.8.9 jar> <names export>` from minecraft-data and
checked against that pack, along with the 1.8.9 texture names, paired up through the two versions' models,
and 1.8.9's English item names from StatsifyDump's `/sdump names`, which tooltips use for unnamed items.

Icons are cached in IndexedDB. Bump `VERSION` in `src/core/icon-cache.ts` whenever a change draws
icons differently, so browsers drop the old ones.

## Text and tooltips

`TextRenderer.load(stack)` reads the pack's default font: ascii.png plus 26.3's accented and
non-Latin sheets, and unifont for everything else. It draws § codes and JSON text components.
26.3 ships unifont (GNU Unifont) with the launcher's assets, not the jar, so a pack only has it
when it carries `font/include/unifont.json` and `font/unifont.zip`. Without them, a CSS font is the
fallback for those characters. `drawTooltip` draws 1.8's tooltip box, and
`tooltipLines` gives an item's name, lore and Unbreakable line, minding HideFlags.

## Inventories

`InventoryRenderer` draws a whole container: the pack's chest screen (or a plain panel for other
sizes), the title, and each slot's icon, count and 1.8.9 durability bar. An item the pack can't
draw leaves its slot empty and logs the error once.

```ts
const renderer = await InventoryRenderer.load(stack);
const canvas = await renderer.draw(slots, { rows: 6, cols: 9, scale: 3, title: "Quick Buy" });
const tooltip = renderer.tooltip(slots[0], 3, 0);
```

It draws on `OffscreenCanvas` in the browser. In Node, like the Discord bot, set the skia-canvas
backend first, and `draw` returns a skia-canvas `Canvas` (typed as `OffscreenCanvas`).
skia-canvas is an optional peer dependency.

```ts
import { setCanvasBackend } from "@statsify/textures";
import { skiaCanvas } from "@statsify/textures/node";

setCanvasBackend(skiaCanvas);
```

## Atlas

An atlas is a pack stack's icons drawn ahead of time: one image, and a JSON map of where each
item's icon sits, so a page can show inventories without loading a pack. `atlas/` holds two:
`vanilla-26.3`, from the 26.3 client, and `vanilla-1.8.9`, with the 1.8.9 client jar over it. Each
image is named by its content hash, so it can be cached for good. The map keeps its name, so serve it
`no-cache`: a regeneration deletes the image an old map names.

```sh
pnpm --filter @statsify/textures build
pnpm --filter @statsify/textures atlas <name> <pack> [<pack> …] [--scales 2,3]
```

3D icons are drawn once at each of `--scales`, and flat ones at 16 pixels, which any whole scale
draws exactly. At another scale, a 3D icon is resized from its largest. Rerun it whenever a change
draws icons differently, as with the icon cache's `VERSION`. It lists the items it can't draw.

Items whose look depends on their stack are still drawn in the browser, from models and textures
the atlas carries: dyed leather, potions, banners, shields and player heads with skins, and the glint
on anything. Atlas icons don't animate.

`loadAtlas(url)` loads one, and it goes wherever a `PackStack` does: `ItemRenderer`,
`InventoryRenderer.load` and `<mc-inventory>`'s `pack`. An atlas has no font, so `<mc-inventory>`
puts its title and counts in HTML, in the page's `Minecraft` font (or `--mc-inventory-font`;
`::part(title)` and `::part(count)` restyle them). It draws no tooltips: it sends
`mc-tooltip-change` events with the hovered `item`, its tooltip `lines` and the pointer, and `null`
once the tooltip should close. `InventoryRenderer.lines(item)` gives the same lines.

## `<mc-inventory>`

```ts
import "@statsify/textures/mc-inventory";

const inventory = document.querySelector("mc-inventory");
inventory.pack = stack;
inventory.slots = fromBedwarsQuickBuy(favorites);
```

```html
<mc-inventory layout="shop" label="Quick Buy" scale="3"></mc-inventory>
```

Attributes: `rows`, `cols`, `scale`, `label` (the title; `title` would also open the browser's
own tooltip), `layout` (`chest`, `large-chest`, `shop`, `hotbar`) and `freeze`, which stops
animations. Tooltips follow the cursor, flip at the window's edges and open on tap.

Every inventory on a page animates on one clock, redrawing only its moving slots, and stops
while it's off screen or the tab is in the background.

## React

```tsx
import { Inventory } from "@statsify/textures/react";

<Inventory pack={stack} slots={slots} layout="shop" label="Quick Buy" scale={3} />;
```

`Inventory` takes the element's properties and attributes as props, and `onTooltipChange` for an
atlas's tooltip events. It's a client component that loads `<mc-inventory>` in the browser, so it's
safe to server render. React is an optional peer dependency.
