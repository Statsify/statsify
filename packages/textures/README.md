# @statsify/textures

Draws Minecraft items, text, tooltips and inventories from a resource pack, in the browser or in
Node. Nothing is pre-rendered and no game assets ship with it: drop in a 26.3 pack
(or the 26.3 client jar) and every icon is drawn from it, then cached.

## Packs

`loadPack` takes a zip or jar as a `Blob`, bytes or a URL. A `PackStack` layers packs the way the
game does, lowest priority first, so a texture-only pack can sit on top of a vanilla one.
Swapping a stack swaps every icon, since cache keys start with the stack's hash.

```ts
import { ItemRenderer, IconCache, PackStack, loadPack } from "@statsify/textures";

const stack = new PackStack([await loadPack(vanillaZip), await loadPack(userPack)]);
const renderer = new ItemRenderer(stack, new IconCache());

const icon = await renderer.render({ id: "minecraft:red_wool" }, 4); // a 64 × 64 canvas
```

Older packs load as 26.3's layout, so they stack over a 26.3 pack the same way. A 1.8.9 pack (or
the 1.8.9 client jar) gives its textures and models under their 26.3 names, and block items draw
from its item models, as 1.8.9 drew them. Its 3D models get the
turn 1.8.9 gave every 3D item in code, its compass and clock strips show the frame a slot shows,
and its glint is tinted and moved the way 1.8 did it. Chests and heads use 26.3's models, which
are drawn in code. Banners aren't supported yet. A stack needs at least one 26.3 pack, which
has the item model definitions.

## Items

- Flat items with tints: leather dye, potion colours, spawn eggs.
- Block items in 3D, through the model's gui transform with the GUI's lighting. A small software
  rasterizer draws them, so they match the game pixel for pixel and need no WebGL.
- Player heads (the default skin, or `item.skin`, a textures.minecraft.net URL, which the page
  can fetch over https), mob heads, chests.
- The enchantment glint, and animated textures by game tick: `render(item, scale, tick)`.

`legacyItem(id, damage)` turns a 1.8 id and Damage value into a 26.3 item. Its table is
generated by `pnpm generate <26.3 jar or pack zip> <1.8.9 jar> <names export>` from minecraft-data and
checked against that pack, along with the 1.8.9 texture names, paired up through the two versions' models,
and 1.8.9's English item names from StatsifyDump's `/sdump names`, which tooltips use for unnamed items.

Icons are cached in IndexedDB. Bump `VERSION` in `src/core/icon-cache.ts` whenever a change draws
icons differently, so browsers drop the old ones.

## Text and tooltips

`TextRenderer.load(stack)` reads the pack's default font: ascii.png plus 26.3's accented and
non-Latin sheets, and unifont for everything else. It draws § codes and JSON text components.
26.3 ships unifont (GNU Unifont) with the launcher's assets, not the jar, so a pack only has it
when it carries `font/include/unifont.json` and `font/unifont.zip`. Without them, a CSS font is the
fallback for those characters. `drawTooltip` draws 1.8's tooltip box, and
`tooltipLines` gives an item's name, lore and Unbreakable line, minding HideFlags.

## Inventories

`InventoryRenderer` draws a whole container: the pack's chest screen (or a plain panel for other
sizes), the title, and each slot's icon, count and 1.8.9 durability bar. An item the pack can't
draw leaves its slot empty and logs the error once.

```ts
const renderer = await InventoryRenderer.load(stack);
const canvas = await renderer.draw(slots, { rows: 6, cols: 9, scale: 3, title: "Quick Buy" });
const tooltip = renderer.tooltip(slots[0], 3, 0);
```

It draws on `OffscreenCanvas` in the browser. In Node, like the Discord bot, set the skia-canvas
backend first, and `draw` returns a skia-canvas `Canvas` (typed as `OffscreenCanvas`).
skia-canvas is an optional peer dependency.

```ts
import { setCanvasBackend } from "@statsify/textures";
import { skiaCanvas } from "@statsify/textures/node";

setCanvasBackend(skiaCanvas);
```

## Adapters

- `fromHypixelNBT(data)`: Hypixel's gzipped NBT, like the Pit's `inv_contents`, as items.
  `playerInventoryOrder` puts a player inventory's hotbar last, as the game shows it.
- `fromBedwarsQuickBuy(favourites)`: the 9 × 6 BedWars shop open on Quick Buy, with each
  item's count, cost and description. `src/adapters/bedwars-shop.ts` holds the shop as
  Hypixel's own NBT has it. Without one, the default quick buy.
- `fromBedwarsHotbar(favoriteSlots)`: a BedWars hotbar from `favorite_slots`, as the Hotbar
  Manager shows it. Without one, the default hotbar.
- `fromDuelsKit(layout, key)`: a Duels `layout_*` kit. The key (`layout_uhc_duel_layout`,
  `layout_mw_duel_herobrine`, `layout_sw_duel_kit_mini_solo_scout`) picks the mode's kit in
  `data/duels-modes.json`, so items get the count, name and tooltip the game gives them, and
  Blitz and SkyWars kits get the armour their picker lists. Armour tokens in older layouts go
  to the armour slots, since the game equips armour. A token no dumped kit has is drawn from the
  Bukkit material it ends in (`hype_train_minecart_7`). Without a layout, it's the game's default
  layout: the single-kit modes in `DUELS_DEFAULT_KEYS` and every kit in `DUELS_KITS`.
- `fromTntGamesLayout(layout, key)`: a TNT Games layout by its `TNTGames` key (`tntrun`,
  `pvprun`, `spleef`, `wizards`, `tnttag`, all in `TNT_GAMES_LAYOUTS`), with the editors' items
  from `data/tnt-games.json`. Without a layout, the game's default one.
- `fromLegacyKit(layout)`: a kit of 1.8 `"id,damage"` values by slot, as Mega Walls'
  `<class>Inventory`, Blitz's `<Kit>Inventory` and classic Walls' `InventoryLayout` send it.
  Walls' newer `InventoryLayout2` adds each item's name (`"273,0,§bSpeedy Spade"`, or `NONAME`),
  which the item gets. It's a slot for every item a player has placed, not one kit: the Layout
  Editor shows the player's current items in those slots, and an item the layout lacks in a free one.
- `fromBlitzKit(layout, kit, level, renames)` and `fromMegaWallsKit(layout, kit, level)`: Blitz's
  `<Kit>Inventory` by the kit's level (1 to 10) and Mega Walls' `<class>Inventory` by the class's
  Kit upgrade (1 to 5), with the "Edit <Kit> Layout" editors' items from `data/legacy-kits.json`.
  A kit's items change with its level, so they get the game's counts, names and tooltips (and Mega
  Walls' armour) only at the level each editor was dumped at, and are plain items at the others.
  `renames` holds the player's `kit_item_rename_<Kit>_<material>` names by material. Without a
  layout, it's the default at that level: `BLITZ_KITS` and `MEGA_WALLS_KITS` list them.
- `fromSkyWarsKit(layout, kit)`: a SkyWars `kit_…_inventory`, which names items by their Bukkit
  material, Damage and enchantment ids (`DIAMOND_AXE:0:16`). `kit` is the kit's id
  (`kit_basic_solo_scout`, as `activeKit_SOLO` holds it) or its key in `SKYWARS_KITS`. Items the
  kit's lobby menu (Normal, Insane, Mini or Mega Kits) lists get the game's counts, names and
  tooltips from `data/skywars-kits.json`, taken from the Kit Customizers and the SkyWars Duel
  editors that hold the same items; a stale item from an older kit version loses its slot to the
  current one. Without a layout, it's the default: the menu's list in order, armour put on and the
  rest from slot 0. `SKYWARS_KITS` lists the kits whose every item is known. Mythical kits are in
  both Normal's and Insane's menus, so they stay plain.
- `fromQuakeLoadout(stats)`: the Quake stats' gun (`case`, `barrel`, `trigger`, `muzzle`, and
  `sight`, its laser), `hat`, `armor` (the Kits menu's chestplate), `leggings` and `boots` as a
  row of 9, with the Quakecraft Shop menus' items from `data/quake.json`.
- `fromArenaLoadout(stats)`: the Arena stats' `offensive`, `utility`, `support` and `ultimate`
  skills and `active_rune` as a row of 5, with the Arena Shop's items from `data/arena.json`.
- `fromTurboKartRacersKart(stats)`: the GingerBread stats' `engine_active`, `booster_active` and
  `frame_active` parts as a row of 3, matched to the part selectors' items in
  `data/turbo-kart-racers.json` by rarity and attribute levels (Basic parts by rarity, since
  they're stored without attributes).
- `fromSpeedUhcKit(id)`: an `activeKit_<MODE>` kit, like `kit_basic_normal_logger`, as a row of
  its items from the Speed UHC Shop's Kits page, and the Default kit from a game's Gear Selector
  (`data/speed-uhc.json`). Only Normal's page is dumped.

In these four, a pick the dumped menus don't have leaves its slot empty.

Every `data/*.json` but `minecraft-data.json` comes from the game: open the layout editors, kit
menus and shop menus with the StatsifyDump module running, then `pnpm build` and
`node scripts/import-dump.ts <dump.json> …`
with the last export of each dump session. Open each kit's editor from its picker before moving
anything: the picker shown next names the kit, and only an unsaved kit shows the default. Blitz's
and Mega Walls' editors open from each kit's Upgrades or Class page, which gives the level.
An item's `tooltip` holds the lines under its name as the game drew them, enchantments and
attributes included.

Kits come back as 40 slots: the hotbar, the three main rows, then boots to helmet in 36 to 39.
`ARMOR_SLOTS` lists the armour slots helmet first, as the inventory screen shows them.

For a skin render, `armorOf(items)` turns items (Pit's `inv_armor`, slots 36 to 39) into
`{ helmet, chestplate, leggings, boots }`, each `{ material, color, enchanted }` or a player head's
`{ head, enchanted }` texture hash; other things on the head, like a mob skull, are left out.
`duelsKitArmor(key)`, `skyWarsKitArmor(kit)`, `blitzKitArmor(kit, level)` and
`megaWallsKitArmor(kit, level)` give a kit's armour by the keys the adapters above take; Blitz's
covers every level from its Upgrades page. Leather is dyed by the name its picker gives (White
Leather Chestplate), else by the picker icon when it shows that piece, else (Blitz) by the colour
its editor shows on that piece. Mega Walls Duel's picker lists no armour, so its classes come back
undefined.
